How the goal is used: it is parsed for budget / RAM / PIN and mapped to a workflow (plan_goal), then logged as a PLAN event you can read in the trace. Explicit parameters below override anything read from the goal.
Domains we have no mocks for (medicine, travel, groceries) are refused with an explicit unsupported_goal ABSTAIN instead of silently running the phone workflow. Open-domain transfer is still a published limitation — see FAILURES.md.
Workflow: two selectable by goal — phone_delivery_check (4 steps) and phone_fulfilment_enquiry (5 steps). Site A VoltKart → Site B SwiftShip.
A goal that asks to contact / enquire switches to the 5-step workflow and performs a real cross-site write (the product from Site A becomes the enquiry subject on Site B), gated by approval.
