## Project identity
- **Name:** SENTRY — a recovery-and-proof layer for browser agents
- **Competition:** SLAB Hackathon, Track 01 (Adaptive Browsing)
- **Thesis:** Replay deterministically. Heal on change. Prove every claim. Abstain when wrong.
- **Not** a shopping agent — the recovery engine is the product; the cross-site workflow is the benchmark/test bench.

## Architecture summary (14 agent .py files, ~1153 lines; harness ~1617 lines)
- **CLI** (`__main__.py`): run / learn / rollback / propose-bump
- **Planner** (`planner.py`): keyword-based NL goal -> workflow + params (budget, RAM, PIN); unsupported domains ABSTAIN
- **Replayer** (`replayer.py`, 312 lines): the core — 4-step workflow (open search -> apply filter -> extract cheapest -> check delivery loop). Detect-recover-verify on every step. Hash chain on stdout. Evidence claims with SHA-256. Constraints check (pass/ABSTAIN).
- **Grounder** (`grounder.py`): 5 fused signals (selector, role+name, text, visual, landmark), weighted scoring, tau=0.70 threshold, synonym tolerance
- **Detector** (`detector.py`): scans for modals, renamed buttons, extra steps, error pages; postcondition verification
- **Recovery** (`recovery.py`): 3-level ladder (re-plan dismiss, re-locate with relaxed signals, backtrack to last-good-URL); never acts irreversibly on unverified state
- **Evidence** (`evidence.py`): extractive-only claims (verbatim snippet + char offset + SHA-256)
- **Constraints** (`constraints.py`): positive proof required ("2-3 days"); rejects negative-tagged strings ("not available")
- **Approval** (`approval.py`): browser modal (primary) + CLI y/N (fallback)
- **Reflect** (`reflect.py`): regression-guarded version bumps; guard runs all 5 variants; ACCEPT/REJECT/ROLLED_BACK logged to versions.jsonl
- **Learner** (`learner.py`): wraps webcmd CLI adapters

# 2026-09-12 (later) — Production hardening pass

## What was done
User asked for production-scale improvements + a browser-window fix + a real adaptive-browsing test bench.

## Changes made
1. **Browser window fix** — new `agent/browser.py`. Headed Chromium now opens maximized, is raised to the
   foreground via Win32 `SetForegroundWindow` (matched by "Chrome"/"Chromium" window class), lands on the current
   screen, holds `--keep-open` ms (default 6000) after the run, `--slowmo` default 250. New flags in `__main__.py`:
   `--slowmo`, `--keep-open`, `--no-raise`, `--channel`. Logs `BROWSER_WINDOW` event. This fixed the user's
   complaint that the tab opened behind everything and finished before it could be seen.
2. **Chaos engine expanded** — `mocks/chaos.js` now has rename, strip, move, attrs, modal, extra_step, throttle,
   ab, swap, composite, chaos_max. `harness/perturbations.py` rewritten as the catalogue (single source of truth).
3. **Structural grounding** — `agent/grounder.py` rewritten: 5-signal fusion now falls back to ARIA role +
   accessible name + label association + SYNONYMS; added `discover()` for structure-first lookup.
4. **Adaptive waits** — `agent/detector.py`: added `settle()` (DOM-quiet MutationObserver) and `wait_for_post()`
   (poll to deadline). `agent/recovery.py` rewritten to use structural relocate + generic dialog dismissal.
   `agent/replayer.py` uses `_fill()` by label, adaptive card extraction from the live list, and adaptive waits.
5. **Mock sites hardened** — site_a/site_b carry aria-labels/roles/landmarks; page-side JS reads structurally
   (`maxPriceEl`/`minRamEl`, `pinEl`/`statusEl`/`checkButton`) so a testid strip doesn't break the site's own logic.
6. **Tests** — 62 total green: `test_mock_contracts.py` (id + structure), `test_chaos_engine.py` (catalogue↔chaos.js
   parity, rename↔synonym parity), `test_grounding.py`, `test_constraints.py` (fast unit), and
   `test_adaptive_live.py` (22 live browser tests over every perturbation).
7. **Console** — generic `/perturb/<type>`, `/api/perturbations` catalogue, 12 chaos buttons, new presets.

## Key bug found & fixed
Judge-operated (live, 600ms-poll) injection ABSTAINed because the agent used a fixed 300ms wait and scanned before
chaos landed (~600ms after load). Replaced with `settle()` + `wait_for_post()`. Live composite now passes with
recovery logged. This was a genuine production-grade fix, not cosmetic.
