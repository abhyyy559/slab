## Project identity
- **Name:** SENTRY — a recovery-and-proof layer for browser agents
- **Competition:** SLAB Hackathon, Track 01 (Adaptive Browsing)
- **Thesis:** Replay deterministically. Heal on change. Prove every claim. Abstain when wrong.
- **Not** a shopping agent — the recovery engine is the product; the cross-site workflow is the benchmark/test bench.

## Architecture summary (14 agent .py files, ~1153 lines; harness ~1617 lines)
- **CLI** (`__main__.py`): run / learn / rollback / propose-bump
- **Planner** (`planner.py`): keyword-based NL goal -> workflow + params (budget, RAM, PIN); unsupported domains ABSTAIN
- **Replayer** (`replayer.py`, 312 lines): the core — 4-step workflow (open search -> apply filter -> extract cheapest -> check delivery loop). Detect-recover-verify on every step. Hash chain on stdout. Evidence claims with SHA-256. Constraints check (pass/ABSTAIN).
- **Grounder** (`grounder.py`): 5 fused signals (selector, role+name, text, visual, landmark), weighted scoring, tau=0.70 threshold, synonym tolerance
- **Detector** (`detector.py`): scans for modals, renamed buttons, extra steps, error pages; postcondition verification
- **Recovery** (`recovery.py`): 3-level ladder (re-plan dismiss, re-locate with relaxed signals, backtrack to last-good-URL); never acts irreversibly on unverified state
- **Evidence** (`evidence.py`): extractive-only claims (verbatim snippet + char offset + SHA-256)
- **Constraints** (`constraints.py`): positive proof required ("2-3 days"); rejects negative-tagged strings ("not available")
- **Approval** (`approval.py`): browser modal (primary) + CLI y/N (fallback)
- **Reflect** (`reflect.py`): regression-guarded version bumps; guard runs all 5 variants; ACCEPT/REJECT/ROLLED_BACK logged to versions.jsonl
- **Learner** (`learner.py`): wraps webcmd CLI adapters
